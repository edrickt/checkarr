## Scope

Whole repository: `README.md`, root/app `package.json`s, all of `apps/server/src/**`, `apps/web/src/**`,
`scripts/**`, `apps/server/scripts/debug-check.ts`, `docker/**`, `.github/workflows/ci.yml`, both vitest
configs, all existing tests. Feature map: scan lifecycle (start/cancel/progress), library sync from
Radarr/Sonarr, integrity checker (ffprobe/ffmpeg classification), purge, re-search, DB schema/migrations,
settings/config/env, HTTP routes + error mapping, auth/security posture (host + CSRF guards), web UI
(dashboard, library table, detail modal, settings, scan hooks, hash router), desktop/tray/service scripts,
CI. Verification of every finding was done against the checked-out code at `5d0c06b` before it was fixed.

## Method

1. Read the README feature/behaviour spec, package scripts, TS configs, CI, DB schema and all source files
   (≈9k LOC); read every existing test to learn intended behaviour and coverage gaps.
2. Confirmed the baseline was green: `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`
   (scripts 50, server 108 passed / 8 skipped, web 29) and `pnpm build`.
3. Hunted for defects by code review plus targeted runtime probes in throwaway processes: Fastify
   `app.inject` against in-memory SQLite, temporary stub Radarr/Sonarr HTTP servers, real media generated
   in `/tmp`, and the real bundled/system ffmpeg binaries. The real `data/` directory, real *arr credentials
   and long-lived servers were never used.
4. For each accepted finding: wrote the regression test first, confirmed it **fails** on the unmodified
   source (temporarily restoring the original file from `HEAD` where useful), then fixed minimally and
   confirmed the full suite green.
5. Re-ran the full official verification (`lint`, `format:check`, `typecheck`, `test`, `build`), the
   macOS desktop-icon install path from CI, and an end-to-end sync→scan probe through the HTTP API.

## Deferred items (with rationale)

1. **Multi-episode files collapse to one row.** Identity is `UNIQUE (source_id, path)` (`apps/server/src/db.ts:48`,
   upsert at `apps/server/src/services/sync.ts:294`), so two Sonarr episodes sharing one file
   (`S01E01-E02.mkv`) become a single row; the second entry overwrites `external_id`/`subtitle`.
   Reproduced with a probe (episodes 11 + 12 → one row, `external_id = 12`), which contradicts the README's
   "every monitored movie/episode gets a row". Fixing needs a schema identity change plus scanner/purge
   assumptions; too risky/ambiguous for this pass.
2. **Explicitly scoped disabled source: purge/re-search sync it but then silently act on nothing.**
   `syncSourcesForBatch` syncs an explicitly selected source even when disabled (matching `/api/sync` and
   scan semantics, `routes.ts:224`), but `purgeFiles`/`researchMissing` filter `WHERE s.enabled = 1`
   (`purge.ts:228`, `research.ts:71`). A dashboard user who selects a disabled source and clicks
   Delete & re-search / Re-search missing gets `total: 0` with no explanation. The UI's Toggle tooltip says
   actions only run against enabled sources, so the intended semantics conflict; product decision needed.
3. **Docker image carries both ffmpeg builds.** The resolver prefers the bundled static binaries on
   linux/x64, so the system ffmpeg installed by the image is only a fallback (now documented). Stripping the
   bundled binaries would change the Docker build with no functional gain; left as-is.
4. **`CHECKARR_PORT`/`PORT` is not validated.** A non-numeric value produces `PORT = NaN` and a cryptic
   `listen` failure at startup (`apps/server/src/config.ts:10`; scripts parse the same env). Fixing cleanly
   needs module-load-time validation shared by the server and the launcher scripts; low impact.
5. **Per-file re-check can overlap a scan that starts while it is decoding.** The new post-sync check closes
   the preparation window, but gating the whole multi-second decode would block scans; the write guard
   (path / purged) makes the residual race benign (last verdict wins, no deletion).
6. **`pnpm start`/`stop`/`launch`/tray keep pid/log/state in `data/` even when `CHECKARR_DATA_DIR` is set.**
   The README only promises that the SQLite directory is overridable; changing every script's state dir is a
   broader behavioural change than this audit should make.
7. **`-max_alloc`/`-max_pixels` decode guards and the classification thresholds were reviewed but left
   unchanged** — exercised with real media: healthy/truncated/audio-only/tail+middle damage classified as
   documented; no defect found.
